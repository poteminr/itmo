## Сеть и формулы

Шесть Conv с ReLU, MaxPool после первой Conv, GlobalAvgPool,
Linear 512→256, ReLU, Linear 256→100. Использована таблица архитектуры
из задания, без BatchNorm. У Conv нет bias, у Linear есть; ReLU inplace.
Режим: FP32, eval, inference_mode. Всего 1 040 324 параметра.

Для S, кратного 16, и целого B:

$$F(S,B)=17714BS^2+313700B.$$

$$M(S,B)=4161296+68BS^2\quad\text{байт}.$$

$$D(S,B)=4161296+380BS^2+8592B\quad\text{байт}.$$

$$T(S,B)=t_0+\sum_{i=1}^{17}\max(F_i/P,\ D_i/W).$$

$$E(S,B)=E_0+P_{base}T(S,B)+e_FF(S,B)+e_DD(S,B).$$

Один MAC равен двум FLOPs; сравнения ReLU и MaxPool не включены.
Память — номинальный пик живых тензоров с весами, входом и временными
int64-индексами MaxPool. Рабочие буферы библиотек не учитываются.
Трафик предполагает однократное чтение входа и весов и запись выхода.
Время предполагает перекрытие вычислений и обмена внутри операции.
Энергия относится ко всему GPU, включая фоновое потребление.

## Запуск

На машине с NVIDIA GPU до 16 GiB и счётчиком полной энергии NVML, например T4:

```bash
python -m pip install torch==2.11.0 --index-url https://download.pytorch.org/whl/cu126
python -m pip install -r requirements.txt
python measure.py --output results-new
python calibrate.py --results results-new
python plot.py --results results-new
```

Существующий CSV не перезаписывается. Для нового прогона нужна новая папка.

## Измерения и калибровка

Сетка: базовые S = 32, 64, 128, 224, 256, 384, 512 и B = 1, 2, 4, 8,
16, 32, 64, 128, 256. При seed 2026 добавлены S = 112, 272, 368, 448 и
B = 33, 229, 252. Всего 132 конфигурации: 63 для калибровки и 69 для проверки.

Каждая конфигурация запускается в отдельном процессе со случайным входом.
`cudnn.benchmark`, `cudnn.allow_tf32` и `cuda.matmul.allow_tf32` выключены.
После 10 прогревочных проходов измеряется полный `max_memory_allocated()`.
Время — медиана 30 проходов с `cuda.synchronize()`.
Энергия — медиана трёх окон длительностью не менее 3 секунд:
разность счётчика NVML в mJ делится на 1000 и число проходов.
CUDA OOM записывается отдельно; остальные ошибки останавливают запуск.

Время калибруется по квадрату логарифмической ошибки с девятью начальными
приближениями. Энергия — по квадрату относительной ошибки с неотрицательными
коэффициентами. Используются только 63 базовые точки. В energy подставляется
предсказанное время; отложенные измерения в подборе не участвуют.

Замеры получены 14 октября 2026 года; полный прогон занял 38 минут 47 секунд.

## Обсуждение

При маленьких входах время определяется постоянными расходами запуска:
рост числа операций ещё не даёт пропорционального роста времени. В модели
этому соответствует t₀. На больших входах растут вычисления и обмен с памятью,
поэтому постоянный член становится менее заметен.

Калиброванная модель отнесла 22 точки к launch-bound и 110 к memory-bound.
Compute-bound точек нет: вычислительный член не активен ни в одном слое
на этой сетке. Поэтому P нельзя интерпретировать как измеренную
производительность T4. Переход memory → compute в этом эксперименте
не установлен. Названия режимов показывают вывод модели; для проверки
причин конкретного ограничения нужен отдельный профиль GPU.

Наибольшие ошибки времени на отложенных точках: S=272, B=2 — 49.6%;
S=32, B=252 — 47.0%; S=32, B=229 — 43.3%. Формулы гладкие, тогда как
реализация может менять алгоритм свёртки и размер рабочего буфера.
Также не учтены кэш, изменение частот и перекрытие запуска ядер CPU
с работой GPU. Эти эффекты могут объяснять расхождения, но сам график
не доказывает конкретную причину.

Память систематически недооценивается. Формула считает тензоры,
а `max_memory_allocated()` включает дополнительные выделения библиотек
и округление аллокатора. В отдельной диагностике S=256, B=1 пик составил
18.60 MiB против 8.22 MiB по формуле. Максимум на всей сетке — 5.745 GiB
при S=512, B=256, поэтому граница OOM не достигнута. CUDA-контекст занимает
физическую VRAM, но не входит в `max_memory_allocated()`.

Энергия измерена для всего GPU; фоновое потребление не вычиталось.
На небольших входах существенны постоянные расходы, на больших — время
выполнения и обработка данных. Признаки F, D и T коррелируют: ранг матрицы
энергии равен 3 из 4, число обусловленности — 1.66·10¹⁶. Поэтому коэффициенты
являются эффективными параметрами прогноза; их нельзя независимо
трактовать как физическую цену FLOP, байта и фоновой мощности.
Результаты относятся к этой GPU, версии библиотек и протоколу измерений.
